# Performance budgets (STAB-5). Format: name  limit  unit  # note
# Checked by the perf guard tests (internal/perfbudget; e2e/perf_test.go)
# in .github/workflows/perf.yml. A number over its limit fails the job.
#
# How to update a budget:
#   1. Measure on your machine, throttled like a CI box:
#        GOMAXPROCS=4 TERMOCODE_PERF=1 go test -count=1 -run Perf -v ./internal/testkit/
#        GOMAXPROCS=4 TERMOCODE_PERF=1 go test -count=1 -run '^TestPerf(Search20kFiles|GitRefresh20k|QuickOpen50k)$' -v ./internal/search/ ./internal/app/
#        GOMAXPROCS=4 TERMOCODE_PERF=1 go -C e2e test -tags e2e -count=1 -run Perf -v ./...
#      Each guard logs "perf: <name> = <got> (budget …)".
#   2. Set the limit to about 2x the local number (CI machines are slower)
#      and write the measured number in the note. Numbers under ~12 ms
#      get a 25 ms floor: scheduler jitter on a shared CI box is that big.
#   3. Raise a budget only for a real reason (say why in the commit).
#      A slower number by accident is a bug to fix, not a budget to raise.
